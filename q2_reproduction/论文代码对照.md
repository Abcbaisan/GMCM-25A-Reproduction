## 1. 先弄清问题一与问题二的分工

```text
官方附件 ZIP：六个计算图 JSON（Nodes、Edges）
                  │
                  ├─ 问题一：q1_reproduction/reproduction_results/
                  │          每个算例的 *_schedule.txt（原始节点的拓扑序）
                  ▼
             q2.py / SpillAllocator
                  │ 读取节点顺序、缓存 Type/Size、ALLOC/FREE、操作 Bufs
                  │ 维护连续地址；不足则 OUT；需要使用或 FREE 前再 IN
                  ▼
    *_schedule.txt  含插入的 SPILL_OUT / SPILL_IN 节点
    *_memory.txt    每个缓冲区首次 ALLOC 时的地址
    *_spill.txt     按 OUT 发生顺序记录每一次 IN 的新地址
                  │
                  ▼
         verify_q2.py：独立重放并计算搬运量
```

问题一给出**原节点的执行次序**；问题二在容量、连续地址、依赖和生命周期约束下给出**物理放置与换出/换入方案**。问题二的评价指标是额外数据搬运量，不是问题三的流水执行时间。`q2.py` 默认固定问题一的原节点相对顺序；`search_schedules.py` 是另外尝试不同合法拓扑序的本地扩展实验，不能与“固定问题一序列”的结果混为一谈。

## 2. 论文方法 → 程序位置 → 可检查行为

| 论文/问题二概念 | 代码定位 | 输入、行为和输出 | 复现性质 |
| --- | --- | --- | --- |

| 内存管理（现有说明归入论文算法 5—7） | `MemoryPool.allocate`、`MemoryPool.release` | 用半开区间 `[offset, offset+size)` 表示连续地址；分配时选能容纳的空闲段，释放后合并相邻段 | 空闲表为可执行补全；`first-fit` / `best-fit` 的具体选择是本地实现细节 |
| 被换出缓冲区选择 | `SpillAllocator.next_use`、`choose_victim` | 从同一种缓存中排除当前操作 `protected` 的缓冲区，再根据策略排序选择受害者 | `paper-small` / `paper-large` 是对现有记录中论文附录/正文两种冲突描述的分别实验，不能说二者同时就是作者唯一算法 |

| 连续空间不足与碎片 | `acquire`、`can_place_needed`、`repack` | 区分总空闲量不足和虽有总空闲却没有足够大的连续洞；必要时真实 OUT/IN 重新排布，不允许零成本搬移 | `repack` 是本地合法性补充，并非声称论文原样给出了这段代码 |
| 完整原节点遍历 | `SpillAllocator.run` | ALLOC：获得地址并写 `memory`；普通操作：确保所有 `Bufs` 同时驻留；FREE：必要时先 IN，再物理释放 | 论文总体调度流程的工程实现 |
| 数据搬运目标 | `spill_out` 中的 `cost`、`self.extra`；`verify_q2.verify_case` 的独立重算 | 每次 SPILL 按缓冲区大小及其是否在原图的 COPY_IN 中出现计费；以搬运量为主、SPILL 对数为次比较候选 | 以题目指标衡量，不把代码中的 `out_cycles/in_cycles` 调试字段混入问题二目标 |

| 合法性检验 | [`verify_q2.py`](verify_q2.py) 的 `verify_case`、`read_result_files` | 不读取求解器的空闲表，而是按地址单元重放正式三文件，检查原依赖、OUT/IN 配对、驻留、类型、边界、地址重叠及成本 | **独立验证器是本地增加的证据，不是论文原算法** |

## 3. 把数学表达式与代码接起来

设第 `k` 次 SPILL 的缓冲区大小为 `s_k`，`c_k=1` 表示该缓冲区出现在**原计算图**某个 `COPY_IN` 操作的 `Bufs` 中，否则为 0。该实现按每一对 OUT/IN 计算

\[
D=\sum_k (2-c_k)s_k.
\]

- **论文/题目层面要问的问题**：需要额外搬运多少数据？同一缓冲区换出多次时，分别计算每一对的成本。
- **代码层面**：`SpillAllocator.__init__` 形成 `self.copyin` 集合；`spill_out` 使用 `size * (1 if b in self.copyin else 2)` 并累加到 `self.extra`；`verify_case` 遍历输出 `spills` 再独立算一遍。例：大小 100、属于 COPY_IN 的缓冲区换出一次计 100；大小 100、非 COPY_IN 的计 200。
- **不要混淆**：`spill_count` 是换出/换入**对数**，不是搬运量；`out_cycles`、`in_cycles` 虽被记录在 `events` 中，却没有参与问题二的候选排序。

连续地址条件也不能只检查“剩余总容量”。若空闲段分别为 `[0,4)` 和 `[7,10)`，总空闲为 7，但没有长度为 5 的连续段。`MemoryPool.allocate(5)` 会失败，随后 `acquire` 需要通过合法的换出来获取连续空间。`MemoryPool.release` 合并的仅是**物理上相邻**的空闲段。

四种容易混淆的状态：`active` 是 ALLOC 后 FREE 前的逻辑存活集合，`resident` 记录实际占用内存的缓冲区和地址，`pending` 记录已 OUT 尚未 IN 的缓冲区，`memory` 记录首次 ALLOC 时的地址；后续 IN 的新地址记录在 `spill` 文件，而不是改写首次分配地址。

## 4. 从一个操作追踪一遍源码

1. 读取原图 `Nodes/Edges` 和问题一的顺序；`__init__` 建立缓冲区元数据、使用位置与五个池，同时排除明显非法的序列。
2. 遇到 `ALLOC(b)`：`run → acquire → MemoryPool.allocate`。成功后把初始地址写入 `memory[b]`。失败时 `choose_victim → spill_out` 释放真实物理空间并产生 OUT 节点，然后重试。
3. 遇到一个普通操作，其 `Bufs={A,B}`：先把二者都列入 `protected`，按类型检查能否共同驻留；必要时 `repack`；对缺失缓冲区调用 `restore → acquire` 插入对应 IN。只有二者全部驻留后，才向最终 `schedule` 添加此操作节点。
4. 遇到 `FREE(b)`：若仍处于 `pending`，先 `restore`，再写入 FREE 并释放物理区间；最后检查全部 `active/resident/pending` 清空、全部内存池归还。
5. `save_result` 写正式三文件；`verify_case` 从最终调度独立重建每个地址单元的占用，检查所有原节点恰好一次、原图依赖、SPILL 先后关系、操作时驻留、地址界限和重叠，并重新计算 `D`。

**阅读顺序建议：**先看 `run()` 把握骨架，再分别跳到 `MemoryPool`、`choose_victim`、`spill_out/restore`，最后看独立验证器。不要直接从文件第一行读到最后一行却不知道每个函数在回答哪个数学问题。
