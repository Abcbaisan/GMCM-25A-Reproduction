# 论文数值对照

两个Matmul算例复现了论文表5.2数值；另外四例通过我们增加的生命周期收缩与反向DFS多起点改进取得更低峰值。它们是可验证的改进结果，不能称为逐项恢复了作者原程序。所有比较均按论文第9页的L1+UB口径，并施加每类L0最多一个缓冲区的约束。

|算例|论文表5.2|公开方法框架+20000次退火|补充改进+2000次退火|相对论文|
|---|---:|---:|---:|---|
|Conv_Case0|7660|17138|6912|低 748（9.77%）|
|Conv_Case1|14040|85868|11631|低 2409（17.16%）|
|FlashAttention_Case0|4500|12470|4498|低 2（0.04%）|
|FlashAttention_Case1|7588|60412|7586|低 2（0.03%）|
|Matmul_Case0|9216|9216|9216|一致|
|Matmul_Case1|34816|34816|34816|一致|

这里没有把不同迭代预算当成严格的算法性能对照。阶段记录用于说明复现过程；本次最终六例的2000次退火均未再改善初值，最终提升来自初始化、生命周期收缩和多起点选择。

## 最终策略与独立峰值校验

|算例|选中的初始策略|改进前该策略峰值|收缩后初值|退火最终值|全类型峰值（另一口径）|

|Conv_Case0|dfs_size_asc|7056|6912|6912|6984|
|Conv_Case1|dfs_front_32|11631|11631|11631|11639|

greedy对应论文附录贪心。dfs_size_asc为我们从FREE按(Size,Id)升序反向展开前驱的DFS扩展；dfs_front_32为Id降序FREE根列表中零基位置32的节点前置。它由对所有算例统一尝试32个根前置的实验自动选出，并非将指定算例或论文目标值硬编码到调度器。

## 可复现命令

在q1.py所在目录并激活FirstPythonEnv后执行：

```bat
python q1.py --case all --iterations 2000 --seed 2025 --l0-single --paper-score --objective l1ub --compact --dfs-variants --dfs-root-trials 32 --out reproduction_results
python verify_results.py --results reproduction_results
```

依赖只有Python标准库。实际运行环境为Python 3.12.4，数据来自用户提供ZIP中的六个JSON。报告中记录了各初始候选、失败候选、种子、温度与收敛轨迹；输出调度均每行一个节点Id。

## 验证与复现边界

全部六条最终序列独立验证通过：节点完整且无重复；每条原始依赖边顺序正确；操作使用的Bufs处于存活期；ALLOC/FREE匹配且最终全部释放；L0A/B/C各至多一个活跃缓冲区；L1+UB与全缓存峰值重算一致。另有小图穷举测试验证重插入和收缩逻辑。

论文缺少完整DFS、SA代码和具体参数，正文与附录部分优先级不一致。严格按公开关键路径逻辑还会遇到L0死锁，我们拒绝失败序列，不使用截断峰值。虽然最终四例低于表值，但没有证明全局最优，也未复现后续问题二、三的硬件地址分配与时序性能。
